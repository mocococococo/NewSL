# PUCT
## ノード（局面情報）
- シート情報（各ストーンの座標）
- ショットするチームが先攻 or 後攻 の情報（ハンマー）
- ショットの投番
- 現在のエンド数
- これまでのエンドで生まれた得点差（ショットするチーム視点）

## エッジ（ショット情報）
- vx（x 方向のショットの初速ベクトル）
- vy（y 方向のショットの初速ベクトル）
- spin（ショットの回転方向、cw or ccw）

# ニューラルネットワーク（CNN）
## 入力
- シート情報（各ストーンの座標）
- ショットするチームが先攻 or 後攻 の情報（ハンマー）
- ショットの投番
- 現在のエンド数
- これまでのエンドで生まれた得点差（ショットするチーム視点）

## 出力
- 与えられた局面で次に打つべき最適ショットの確率分布
    - vx
        - x 方向のショットの初速ベクトル
        - -0.25 ~ +0.25 の範囲で 32 等分割で離散化されている
    - vy
        - y 方向のショットの初速ベクトル
        - +2.2 ~ +3.5 の範囲で 32 等分割で離散化されている
    - spin
        - ショットの回転方向、
        - cw or ccw で 2 パターン
    - つまり、32 × 32 × 2 の離散空間の確率分布となる
- ValueHeadは存在しない

# AIの行動選択の流れ
- 局面情報を取得
- UCT開始 (複数エンドは跨がない)
    - ニューラルネットワークに局面情報を与えて、最適ショットの確率分布 S を得る
    - 遷移するエッジを PUCT の (Q + U)に基づいて選択する
        - progressive widening を採用して、M(c) 個だけを候補手に入れる
    - エッジに対して以下を実行する
        - エッジのショットを実行し、高速シミュレータを使用したシミュレーションを行い、子ノードを展開する
        - 展開した子ノードでエンドが終了しスコアが出るなら、それ以上の子ノードは展開せず、スコアを報酬として先祖に伝播する
            - エンド終了判定は投番 == 15(0-index) かどうかで判断する

## 候補手定義
- Q + U の argmax となる候補手を訪問する
    - Q: 価値 / 訪問回数
    - U: cpuct × ニューラルネットワークのポリシー確率 × 親の訪問回数 / (1 + 訪問回数)
- 展開候補のノードの個数 M(c) 選択方法
    - M(c) = max(c, ⌊k × c^a⌋)
    - k, a, c はハイパーパラメータ
- ニューラルネットワークから出力される候補手2048の時点でかなり細分化して離散化されているため、ノイズは加えない

## 報酬定義
- -8 ~ +8 のスコアを[-1, 1]の範囲で線形正規化して常に各ノードのto-play視点で符号反転しようと思います。
- エンド終了まで子ノードの展開は続くため、スコア未確定の状態は起こらないと考えています。

## 局面評価
- 実装の難易度を考慮して、バッチ推論は行いません。1つの局面に対して1回局面評価を行います。

# 事前Q&A
- ロールアウト方針
    - エンド終了まで（スコアが出るまで）深さを増やし続けます。
    - 複数エンドは跨ぎません。
    - 深さの上限はエンド終了までです。途中で打ち切りはしません。
- エンド内での相手手番の選択方針
    - 相手の手番も、局面をニューラルネットワークに与えてPUCTで選ぶ方針です。候補制限等はしません。
- シミュレータの決定論 / 確率性
    - シミュレータに責任を持たせます。探索側では考慮しない方針です。
- 計算予算
    - まだどのくらいかかるか分かっていません。
    - シミュレーション回数制限や秒数を探索実行時の変数として持たせることで、調整できるようにしたいです。実際に実行して、実行時間を見ながら決めたいです。
- ルール制約
    - フリーガードゾーンルール等の制約はシミュレータに責任を持たせます。もし違反していれば、シミュレータからはショット前と同じ状態のシート情報が返ってきます。シート情報が一致しているか確認して、一致していれば False(ショットが違法), 一致していなければ True(ショットが合法) という情報も返すラッパを作ろうと思っています。もしFalseならノードに移動せず、以後そのエッジを候補手から除外します。
- 状態ハッシュを使うか？
    - エンド数、投番、シート情報が全く同じ局面になることは考えにくいため、同一局面の再訪のTTは使用しない。
- ニューラルネットワークについて
    - すでにポリシーを学習済み
    - 2048 の候補手をsoftmaxで出力
- 推論時間
    - 実行してみないと分かりません。
- シミュレーション時間
    - 実行してみないと分かりません。
- 探索の並列化
    - しません。
- 実行環境
    - CPU: AMD Ryzen9 9900X 12-core Processor
    - GPU: Nvidia RTX4070Super 12GB
    - RAM: 32GB
- ゲームのエンド数
    - 10
- スコア計算の仕様
    - ティー中心座標、in-house 判定の閾値に石半径を含める
- progressive widening の c の定義
    - 親ノード訪問回数 N(s) でよい
- 未訪問エッジの Q 初期値
    - 0 でよい
